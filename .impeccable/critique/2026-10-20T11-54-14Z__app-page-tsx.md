## Overall Impression

The hero is the strongest part of the whole app's public face — the ladder visual genuinely sells the product's actual mechanic instead of a generic feature list. What's missing is follow-through: the page loses its own focus-ring system on every single interactive element, restates its stats instead of using that space for a second chance to convert, and has no CTA left standing once a visitor scrolls to the bottom.

## Priority Issues

**[P1] Every interactive element on the page loses the design system's focus ring**
- **Why it matters:** Confirmed via grep — zero `focus-visible`/`focus:ring` occurrences anywhere in `app/page.tsx`, across all 7 links (logo, nav CTA, both hero CTAs, both footer links). This exact class is applied consistently in `app/dashboard/layout.tsx`, the auth pages, and `QuizCard` — the landing page is the one surface missing it, and it's the one every visitor hits first. Keyboard users get the browser's default blue outline on the app's primary conversion button.
- **Fix:** Add `focus-visible:outline-none focus-visible:ring-[3px] focus-visible:ring-focus-ring` to the nav Link, both hero CTA Links, the auth nav CTA, and the footer Links.
- **Suggested command:** `/impeccable harden`

**[P1] No closing CTA — the page ends in footer links only**
- **Why it matters:** Confirmed in source — after the feature cards and the bottom stats row, the page goes straight to a footer with only "Politique de confidentialité" / "CGU" links. A visitor convinced by the time they finish reading has to scroll back to the top to find "Commencer." On a Persuade surface, this is friction at the exact moment of highest intent.
- **Fix:** Replace or follow the bottom stats row with a compact closing CTA block (headline + "Commencer" button).
- **Suggested command:** `/impeccable layout`

**[P2] Mobile nav wordmark has no responsive hide, unlike the dashboard nav**
- **Why it matters:** Confirmed by direct comparison — `app/dashboard/layout.tsx` hides its "CodeInQuest" wordmark below `sm` (`hidden sm:block`), matching DESIGN.md's own documented Navigation spec ("the brand wordmark hides below `sm`, leaving only the chest icon"). The landing page's nav wordmark has no such class. This is the one nav an unauthenticated first-time mobile visitor actually uses, with logo + full wordmark + a right-aligned CTA all competing for ~358px.
- **Fix:** Add `hidden sm:inline` to the wordmark span, matching the dashboard's pattern. Since the logo's `alt=""` currently relies on the adjacent wordmark as the text alternative, give the icon a real `alt="CodeInQuest"` below `sm` once the wordmark is hidden there (or make the hidden span still reachable to screen readers via `sr-only` instead of `hidden`, to avoid losing the accessible name on mobile).
- **Suggested command:** `/impeccable harden`

**[P2] The same three stats are stated twice on one page**
- **Why it matters:** "7 divisions / 6+ quiz / 30+ questions" appears under the hero copy, then again (plus a fourth, "3 Niveaux") in a full-width row near the bottom. Reads as padding rather than reinforcement, and uses up the one slot where fresh closing content (the P1 CTA fix) could go instead.
- **Fix:** Remove the inline hero mini-stats (the ladder already proves scope) and repurpose the bottom block as the closing-CTA section from P1.
- **Suggested command:** `/impeccable distill`

**[P3] Full-page loading flash on every fresh visit**
- **Why it matters:** The entire hero/ladder/features/footer is gated behind `status === 'loading'` from `useSession()`, even though only the nav's single CTA label ("Se connecter" vs "Mon compte") actually depends on auth state. Every first paint — the moment that matters most on a Persuade surface — shows a blank "Chargement..." screen instead of the marketing content.
- **Fix:** Render the static content unconditionally; default the nav CTA to "Se connecter" and swap only that element once `status` resolves.
- **Suggested command:** `/impeccable optimize`
